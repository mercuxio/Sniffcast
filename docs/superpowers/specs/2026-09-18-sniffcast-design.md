# Sniffcast — Design Spec

**Date:** 2026-09-18
**Status:** Approved design, pending spec review

Sniffcast is a macOS menubar app that shows current weather and air quality (AQI) at a glance, with a dropdown panel for detail. It must be resource-efficient enough to run all day unnoticed.

## 1. Scope

### In v1
- Menubar item with three user-selectable styles (§4).
- Dropdown panel: current conditions, pollutant breakdown, hourly forecast (next 12 h), daily forecast (7 days) with pollen where available.
- Location: device location via Location Services, and/or cities found by search. Multiple saved locations, switchable from the panel.
- Units: °F/°C, mph/km/h, US AQI / European AQI.
- AQI threshold notifications.
- Launch at login.

### Out of scope (v1)
- Mac App Store distribution (code stays sandbox-compatible, but no App Store entitlements, receipts, or review work).
- Widgets, iOS companion, historical charts, radar/maps.
- Commercial use of Open-Meteo (the free tier is non-commercial; revisit before any paid release).

## 2. Platform & tooling

- **Target:** macOS 15.0+, Swift 6 language mode (strict concurrency), `@Observable` state.
- **Project:** Xcode project generated by **XcodeGen** from `project.yml`; the generated `.xcodeproj` is not committed.
- **App type:** agent app (`LSUIElement = YES`) — no Dock icon, no main window.
- **Distribution:** local builds; optionally Developer ID signed + notarized later.
- **Dependencies:** none beyond Apple frameworks (AppKit, SwiftUI, Swift Charts, CoreLocation, Network, UserNotifications, ServiceManagement).

## 3. Architecture

Hybrid: **AppKit `NSStatusItem`** for the menubar label (colored text / non-template images are required, which `MenuBarExtra` cannot render), hosting a **SwiftUI panel in an `NSPopover`**.

```
Sniffcast/
  App/         SniffcastApp (entry), AppDelegate — wires status item, popover, services
  StatusBar/   StatusItemController — renders the 3 styles, rotation timer, AQI colors
  Data/        OpenMeteoClient — forecast, air-quality, geocoding (async/await, Codable)
  Domain/      Models (Conditions, HourlyPoint, DailyPoint, Pollutants, Pollen), AQIScale (US/EU bands, labels, colors), Units
  Location/    LocationProvider (CoreLocation wrapper), SavedLocationsStore
  Services/    RefreshScheduler, AlertService
  Settings/    SettingsStore (UserDefaults-backed), SettingsView, LoginItem (SMAppService)
  UI/          PanelView, CurrentCard, PollutantGrid, HourlyChart, DailyList, LocationPicker
SniffcastTests/
```

### Unit boundaries
| Unit | Responsibility | Depends on |
|---|---|---|
| `OpenMeteoClient` (protocol `WeatherProviding`) | Fetch + decode API responses into domain models | `URLSession` |
| `LocationProvider` (protocol `LocationProviding`) | One-shot fix + significant-change updates; authorization state | CoreLocation |
| `SavedLocationsStore` | Persist ordered list of locations + active selection | UserDefaults |
| `SettingsStore` | Units, AQI scale, menubar style, alert config | UserDefaults |
| `AppState` (`@Observable`, `@MainActor`) | Single source of truth: active location, latest `Snapshot`, fetch status, staleness | — |
| `RefreshScheduler` | Decide *when* to fetch; call provider; write `AppState` | provider, `NSBackgroundActivityScheduler`, `NWPathMonitor` |
| `AlertService` | Evaluate threshold after each refresh; post notification with hysteresis | `AppState`, UserNotifications |
| `StatusItemController` | Render menubar from `AppState` + `SettingsStore` | AppKit |
| Panel views | Present `Snapshot`; no fetching logic | `AppState` |

### Data flow
`RefreshScheduler` → `WeatherProviding.fetch(location)` → `Snapshot` → `AppState` → observed by `StatusItemController`, panel views, and `AlertService`.

## 4. Menubar rendering

Styles (selectable in Settings):
1. **Full:** condition SF Symbol + temperature + `AQI n`, AQI number tinted by band color.
2. **Compact:** condition symbol + temperature + colored `●` for AQI band.
3. **Rotating:** alternates weather (symbol + temp) and AQI (`AQI n`, tinted) every 8 s.

Rules:
- Title is an `NSAttributedString`; redraw only when the rendered string changes.
- Band colors are adjusted for light/dark menubar appearance to keep ≥ 3:1 contrast.
- Stale data (§7) shows a subtle dimmed style; the item never goes blank. Before first data: symbol + `—`.
- Clicking toggles the popover; popover uses `.transient` behavior.

## 5. Data source: Open-Meteo

No API key. Two requests per refresh, requesting only displayed fields:

- **Forecast** `https://api.open-meteo.com/v1/forecast`
  - `current=temperature_2m,apparent_temperature,relative_humidity_2m,weather_code,wind_speed_10m,is_day`
  - `hourly=temperature_2m,weather_code` with `forecast_hours=12`
  - `daily=weather_code,temperature_2m_max,temperature_2m_min`, `forecast_days=7`
  - `temperature_unit` / `wind_speed_unit` per settings, `timezone=auto`
- **Air quality** `https://air-quality-api.open-meteo.com/v1/air-quality`
  - `current=us_aqi,european_aqi,pm2_5,pm10,ozone,nitrogen_dioxide,sulphur_dioxide,carbon_monoxide`
  - `hourly=us_aqi,european_aqi` (next 12 h) and pollen (`alder_pollen,birch_pollen,grass_pollen,mugwort_pollen,olive_pollen,ragweed_pollen`) over the forecast window
  - Pollen is hourly-only and Europe-only; daily pollen = per-day max of hourly values. If all null → pollen section hidden.
- **Geocoding** `https://geocoding-api.open-meteo.com/v1/search?name=…&count=8` for city search (debounced 300 ms, min 2 chars).

Both refresh requests run concurrently (`async let`). A `Snapshot` is only committed if the forecast succeeds; air-quality failure yields a snapshot with AQI marked unavailable.

## 6. Resource efficiency (hard requirement)

**Budgets:** idle CPU ≈ 0%; idle memory (panel closed) **< 40 MB** physical footprint; Activity Monitor energy impact "Low"; no process wakeups between refreshes except the rotating-style timer.

| Area | Design |
|---|---|
| Refresh cadence | `NSBackgroundActivityScheduler`, interval 30 min, tolerance 5 min, `qualityOfService = .utility`. |
| Wake / network | On wake or network regained: fetch only if snapshot age > 30 min. `NWPathMonitor` suppresses fetches while offline. |
| Manual refresh | Panel open triggers a fetch only if data is > 10 min old. |
| Network | One shared `URLSession` (default config, `URLCache` 1 MB memory / 5 MB disk); minimal query fields; gzip is automatic. |
| Location | `desiredAccuracy = kCLLocationAccuracyKilometer`; one `requestLocation()` on start, then `startMonitoringSignificantLocationChanges()`. Never continuous updates. Saved cities use no location services. |
| Menubar | Redraw only on changed output. Rotation timer exists only in rotating style, `tolerance = 0.8 s`, paused on screen lock (`com.apple.screenIsLocked`) and display sleep (`NSWorkspace.screensDidSleepNotification`). |
| Panel | `NSHostingController` created on popover open and released on close, so SwiftUI/Charts memory is not retained while idle. |
| Process | App Nap left enabled; no background threads or polling loops; login item via `SMAppService.mainApp` (no helper). |
| Alerts | Evaluated inline after each refresh — no timers. |

**Verification checklist (must pass before v1 is "done"):**
- Activity Monitor → Energy tab after 30 min idle: "Low", no sustained CPU.
- `footprint Sniffcast` with panel closed: < 40 MB.
- 10-min Instruments trace (Time Profiler + Energy Log) in Full style: no activity between refreshes.
- Same trace in Rotating style: only timer wakeups at ~8 s cadence, none while screen is locked.

## 7. Errors & edge cases

- **Fetch failure:** keep last good snapshot, mark stale if age > 45 min (dimmed menubar, "Updated 2 h ago" in panel). Retry with exponential backoff (2, 4, 8 min, capped at the 30-min interval), scheduled via the same scheduler — no retry storms.
- **Location denied / unavailable:** fall back to the first saved city; panel shows a one-line prompt linking to System Settings. If no saved city exists, panel shows location setup.
- **No AQI coverage / nulls:** menubar shows weather only for that field; panel hides empty sections.
- **Invalid geocoding results / empty search:** inline "No matches" message.
- **Notifications not authorized:** alert toggle shows a hint; no repeated prompts.

## 8. Settings & alerts

Settings window (SwiftUI `Settings` scene, opened from the panel's gear button):
- Menubar style (Full / Compact / Rotating)
- Temperature °F/°C, wind mph/km/h, AQI scale US/EU (defaults from system locale)
- Locations: "Current location" toggle, search + add, reorder, delete
- AQI alert: on/off, threshold (default 100 US / 60 EU)
- Launch at login (`SMAppService.mainApp.register()/unregister()`)

**Alert hysteresis:** notify once when AQI rises to ≥ threshold; re-arm only after it falls to ≤ threshold − 10 (US) / − 5 (EU). State tracked per location.

## 9. Testing

Unit tests (`SniffcastTests`, Swift Testing):
- `AQIScale`: band boundaries, labels, colors for US and EU scales.
- Decoding: saved Open-Meteo JSON fixtures (normal, nulls, missing pollen, error payload).
- `AlertService`: threshold crossing, hysteresis, per-location state.
- Units: conversions and formatting.
- `RefreshScheduler` staleness decisions, using a fake clock and fake `WeatherProviding`.

Network and location are behind protocols so tests use fakes; no live network in tests. UI verified manually plus the efficiency checklist in §6.
